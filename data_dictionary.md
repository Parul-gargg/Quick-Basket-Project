# QuickBasket Data Dictionary

This document describes the five CSV files used in the QuickBasket Analytics project. The dataset is simulated/synthetic and is intended for analytics practice.

## Table overview

| File | Rows in current dataset | Grain | Primary identifier / key |
|---|---:|---|---|
| `customers.csv` | 6,000 | One registered customer | `customer_id` |
| `products.csv` | 139 | One product / SKU | `product_id` |
| `orders.csv` | 25,028 | One order | `order_id` |
| `order_items.csv` | 101,989 | One product line within an order | `order_id` + `product_id` |
| `marketing_spend.csv` | 21,930 | One channel/city/day record | `date` + `channel` + `city` |

| Column | Meaning | Typical type | Used in current notebook |

| `order_date` | Date of the order | Date | Yes |

### Important interpretation

The portfolio version uses **Delivered** orders as the revenue/profitability base. Cancelled and returned orders remain in the original orders table so that operational rates can be analysed separately in future work.

## 4. order_items.csv

| Column | Meaning | Typical type | Used in current notebook |
|---|---|---|---|
| `order_id` | Order containing the product line | Text | Yes |
| `product_id` | Product purchased | Text | Yes |
| `quantity` | Number of units purchased | Numeric | Yes |
| `unit_price` | Selling price paid per unit | Numeric | Yes |

### Important grain concept

One order can contain multiple product lines. Therefore, this table can have several rows for the same `order_id`. Order-level metrics such as AOV must account for this grain.

# Derived fields created in the notebook

| Derived field | Logic / meaning |
|---|---|
| `revenue` | `quantity × unit_price` for delivered order items |
| `cost` | `quantity × cost_price` |
| `margin` | `revenue − cost` |
| `order_month` | Month extracted from `order_date` |
| `day_of_week` | Day name extracted from `order_date` |
| `is_weekend` | True for Saturday/Sunday, otherwise False |
| `recency` | Days since each customer's latest order |
| `frequency` | Number of unique orders per customer |
| `monetary` | Total revenue generated by a customer |
| `R`, `F`, `M` | RFM scores assigned to recency, frequency and monetary behaviour |
| `RFM_score` | Concatenation of R, F and M scores |
| `segment` | Project-specific RFM customer segment |

# Key relationships

```text
customers.customer_id  ───────<  orders.customer_id
orders.order_id         ───────<  order_items.order_id
products.product_id     ───────<  order_items.product_id
```

The analytical master table is built by combining:

```text
orders
   + order_items
   + products
   + customers
        ↓
analysis master table
```

The resulting master table is at the **product-line-within-order** level.

# Important business metrics

### Revenue

Money paid by customers for the delivered product lines included in the analysis.

### Cost

Product cost associated with the units sold.

### Gross Margin

Revenue remaining after product cost:

`Gross Margin = Revenue − Cost`

### Margin %

The percentage of revenue retained after product cost:

`Margin % = Gross Margin / Revenue × 100`

### AOV

Average revenue per unique order:

`AOV = Total Revenue / Number of Unique Orders`

### RFM

- **R — Recency:** how recently the customer ordered
- **F — Frequency:** how often the customer ordered
- **M — Monetary:** how much revenue the customer generated
